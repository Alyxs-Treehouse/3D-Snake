# 性能预算与测量

## 已落实的约束

- 蛇的头、鼻尖各一个 MeshInstance，身体和连接段各一个 MultiMesh：**4 个渲染节点**，不随长度增长。
- 按关卡容量预分配实例和位置缓冲，增长 / 重开只调整可见数量；每帧不创建 Mesh、Material 或节点。
- 房间静态线框按材质批量绘制；切关卡时才重建。MultiMesh 使用明确的房间 AABB，避免逐帧重新求边界。
- 中立输入的插值参数不变时跳过蛇的变换提交；HUD 每 0.1 秒刷新，只写变化的文本。
- 占用格查询与食物随机选点使用索引表和可用格数组，单次查占用、选择食物为 O(1)。初始化扫描关卡容量；蛇身数组头插和视觉更新仍为 O(蛇长)，不宣称整个移动事务为 O(1)。
- 机制只在逻辑步调用，存档只在得分结算、教程完成或外观选择等事件写入。输入映射每帧更新，确保回中迅速停止。

实现依据：[Godot 4.4 MultiMesh](https://docs.godotengine.org/en/4.4/classes/class_multimesh.html)。GPU instancing 降低同网格重复提交开销，但单批次共享可见性范围，所以保持边界限定在当前房间。

## 本机 CPU 对比记录

2026-11-16，macOS / Apple M1 Pro，Godot 4.4.1，headless。每个长度运行 300 次动画更新，前 60 次作为预热，统计剩余 240 次。对照是 Git 标签 `v0.3.3` 的渲染实现，输入为相同数量的格子；仅测变换更新和提交的 CPU 时间。

| 蛇长 | 原蛇渲染节点 | 当前蛇渲染节点 | 原 P95 | 当前 P95 |
| --- | ---: | ---: | ---: | ---: |
| 3 | 6 | 4 | 0.003 ms | 0.002 ms |
| 64 | 128 | 4 | 0.052 ms | 0.029 ms |
| 256 | 512 | 4 | 0.211 ms | 0.121 ms |
| 512 | 1024 | 4 | 0.468 ms | 0.240 ms |

512 节下本次 P95 约降低 49%。这里只统计蛇本身节点，不把房间 / HUD 算入对照。原始记录为本地 `builds/performance.json`。运行 `./tools/dev.sh benchmark` 可在当前机器重新测量；数值会受机器和负载影响，不作为跨机器硬性阈值。

**此结果不是 GPU 测量，也不代表 PICO 4 的帧率提高 49%。** 它不包含 OpenXR 合成、双眼栅格化、手部追踪、温度或系统调度。

## 设备验收预算

以已有 PICO 4 的 72 Hz 运行模式为目标，帧预算约 13.9 ms。后续机制和素材按这些目标验收：

| 项目 | 目标 / 方法 |
| --- | --- |
| 游戏 CPU 更新 | 目标 P95 < 2 ms；在真机长蛇场景测量 |
| 整体帧时间 | 目标持续满足 72 Hz，并保留余量；分别观察 CPU / GPU |
| 长时间运行 | 至少 20 分钟，记录掉帧、温度趋势、内存增长和切后台恢复 |
| 长蛇 / 最大关卡 | 经典容量 512 格；新增更大关卡须重测，当前配置上限 4096 格 |
| 节点 / 资源增长 | 重复重开、切关卡、换皮后，节点和材质数量应回到稳定水平 |

这些是工程验收目标，0.4.0 尚未完成设备长期性能验收。不要把实验室历史 72 FPS 短采样、桌面 CPU 基准或自动测试替代真机结论。新机制、复杂材质和其他设备需要重新测量。
